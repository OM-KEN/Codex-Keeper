# 开发说明

## 构建与运行

需要 Apple Silicon Mac 和 Xcode Command Line Tools（`xcode-select --install`）。在项目根目录运行：

```sh
./run-tests.sh
./build.sh
open .build/CodexKeeper.app
```

原生 Swift / SwiftUI / AppKit 应用，无 xcodeproj。`build.sh` 的 SOURCES 显式列出 Swift 文件；新增源文件要更新列表。版本来自 `VERSION`，部署版本来自 `Info.plist`。

界面支持简体中文与英语，跟随 macOS 为应用选择的语言。中文文案作为 `L10n` 的回退键，英文位于 `en.lproj/Localizable.strings`；新增面向用户的文字须补齐英文键值。`build.sh` 将两种语言资源复制入 App，并把它们计入构建指纹。设置中的默认续跑内容不可编辑，按当前语言发送“继续”或“Continue”；选择自定义后通过弹窗保存内容，切回默认时保留自定义文字以便再次选择。旧偏好没有明确模式时，保存的内置默认值按默认处理，其他非空内容和已标记的自定义值按自定义处理；旧版手动改回与默认值完全相同的文字无法区分，按默认值处理。

默认优先使用本机 Apple Development 证书，没有证书则使用临时签名，因此其他开发者不需要作者证书也能编译。可设置 `CODE_SIGN_IDENTITY`。构建先在临时目录完成并验证签名，再替换目标应用；运行中的目标应用不会被覆盖。使用 `BUILD_DIR=.build/candidate ./build.sh` 可以保留当前运行版本。

## 适用范围与兼容性

- **平台**：Apple Silicon、macOS 13+。部署下限与验证机器上官方 Codex 应用声明的 13.0 一致；已通过该目标编译，尚未在 macOS 13 真机验证。macOS 13 使用原生编辑器样式，14+ 使用 plain 样式。
- **已核验客户端**：2026-09-16，本机 Codex 26.908.70816（9275），内置 CLI 0.154.0-alpha.6.2。此版本的官方应用包名为 ChatGPT.app，bundle ID 为 com.openai.codex。
- **账户**：ChatGPT 登录；API key 和其他登录方式不支持。账户 ID 优先使用额度响应，缺失时核对本地认证文件的稳定 account_id；冲突、缺失或读中变化均暂停自动操作，不以邮箱代替身份。
- **安装路径**：优先运行中的官方 Codex 应用，其次系统及用户 Applications 中的 Codex.app / ChatGPT.app，再检查绝对 PATH 和常用 Homebrew 路径。
- **数据目录**：统一使用 `CODEX_HOME`，未设置则为 `~/.codex`；由 Finder 启动时不会自动继承 shell 配置里的环境变量。自定义目录必须传入启动环境，且与目标 Codex 使用同一目录。
- **任务范围**：当前 Mac 的本地任务；不承诺云端、远程主机和其他操作系统。
- **故障处理**：按日志及 WAL 修改时间发现当前 `logs*.sqlite`，轮换或截断时重读。格式不兼容、已有任务却无法读取日志时暂停自动操作；发送前重新验证目标仍有同一次额度停止证据。新用户没有任何任务或日志时显示空任务列表。

官方接口用于账户、额度、模型发现和独立 app-server 续跑。桌面 IPC、rollout、日志数据库、认证和草稿文件仍含非公开兼容层，因此不能承诺支持 Codex 的所有历史与未来版本。升级 Codex 后应重新核验；无法可靠确认时停止并显示错误。

资料：[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)、[Codex 模型](https://learn.chatgpt.com/docs/models)、[Codex 应用](https://learn.chatgpt.com/docs/app)。应用网页确认 Apple Silicon 支持，macOS 13 下限来自上述安装包的 Info.plist。

## 安装包与发布

DMG 使用 Copied 的拖入 Applications 布局。打包依赖 Python 3.10+ 和 dmgbuild 1.6.7，建议装在虚拟环境中：

```sh
python3 -m venv .build/dmg-tools
.build/dmg-tools/bin/python -m pip install 'dmgbuild==1.6.7'
PYTHON=.build/dmg-tools/bin/python ./create-dmg.sh
```

输出为 `.build/CodexKeeper-<VERSION>.dmg`。按 Copied 的方式分发：优先使用 Apple Development 签名，没有证书时使用临时签名，不要求 Developer ID 或公证。`--release` 可用于发布构建，与默认构建使用同一签名策略。

对外发布前运行回归、构建及安装包验证，接入正式 App 图标，确定协议、版本和 GitHub 仓库，并生成最终安装包的校验和。提交、推送及发布仍需维护者明确同意。另一台 Mac 的首次安装、登录读取、登录项、保活及续跑验收，以及 macOS 13 真机验证仍待完成。

未公证应用首次打开可能被系统拦截；用户确认来源后，可按 [Apple 的打开说明](https://support.apple.com/zh-cn/102445)操作。不要把开发签名描述为公证签名。

## 首次启动

新用户依次看到品牌页、保活与时间设置页、自动续跑介绍页。品牌页当前使用系统心电图符号占位，正式 App 图标接入时同步替换。开始时间默认 08:00，后三个计划时间即时联动，跨天标注“次日”；支持返回调整。页面整体左对齐，保留“1.”与“2.”编号，标题与正文保持清晰层级；窗口统一为紧凑宽度，高度跟随每页内容，切换时保持顶部位置。使用 AppKit 先淡出整页、调整窗口高度、再淡入新页，避免文字在尺寸变化中重新排列；减少动态效果时省略尺寸动画。返回位于左下角，下一步位于右下角，计划时间位于标签下方。最后点击“开始使用”才保存并启动菜单栏服务。完成前不会初始化额度读取或自动执行。关闭引导会退出，下次打开再次显示；完成后不再重复。已有设置的用户升级时沿用原偏好，不显示引导。

## 现役行为

- 已接真实执行。每天以用户设定的开始时间为锚点，间隔 5 小时安排四个节点。
- Codex 桌面应用退出后，只要 Keeper 仍运行且 CLI 可用，额度查询与定时保活仍可在后台工作；续跑找不到桌面任务写入者时尝试独立 app-server 通道，不保证每次都能继续。
- 计划节点后 3 分钟属于同一轮；不能提前发送，额度恢复时间保持真实，错过整轮不补保活。
- 无待续任务时按节点保活；已有有效窗口则跳过。周额度耗尽会阻止发送。
- 有真实额度错误证据且仍未恢复运行的任务，默认全部自动继续；正常完成且额度恰好为 100% 不算撞墙。
- 用户自行继续、终止或任务状态变化后会重新检查，防止重复续跑。
- 可选择待续任务、设置每个任务的固定内容，或读取该任务在 Codex 中已保存的输入框文字。草稿为空时发送“继续”，保留原草稿，仅发送文字，无法可靠读取的格式报错。
- 设置中的“继续前提醒 Codex 检查项目”默认开启：项目文件记录变化或无法核对时，在选定内容前附加“Keeper 自动续跑提醒：请先检查项目当前文件和任务进度，再继续。”；关闭后只发送选定内容。提醒不代表已经确认暂停期间有文件变化。
- “取消下一次自动继续”二次确认后仅取消当前这些额度停止事件；未来再次撞墙仍默认续跑。
- 每日开始时间之前的 5 小时属于锚点保护区；实际决策见 `Core/DecisionEngine.swift`。
- 连续观测的自然恢复识别核对预期恢复时间前后 90 秒内的同账户读数。错过该区间时，仍可使用已确认额度停止事件中保存的恢复时间：同账户、该时间已到且实时额度恢复后允许续跑，不依赖相邻两次采样。该补偿不覆盖明确的按计划等待选择和锚点保护；未知恢复时间、提前归零、账户变化、额度仍耗尽均不放行。发送前继续核对同一停止事件、任务状态与重复尝试记录。
- 任务 rollout 仅接收 `codex` 额度或无 ID 的旧格式，其他限额类别的空窗口不能覆盖已有普通额度。明确额度停止时若最后任务读数仅为 99%，不猜测耗尽窗口；后续同账户实时 100% 读数可补齐对应停止事件的恢复时间，保存在现有 `pending-runtime.json` 的 `confirmed` 中。重新扫描、断网及重启保留同一事件的证据，新停止事件不继承旧期限。
- 额度读取与任务扫描每 20 秒进行；启动、打开菜单、唤醒、网络和系统时间变化会刷新；发送前再确认额度、账户、任务和工作区状态。

## 额度连接与流量

- `AppState` 为 `UsageObserver` 和 `ExecutionCoordinator` 注入同一个 `AppServerUsageProvider`；正常读取复用一个额度专用 app-server，不再每次启动进程。
- 每次仍请求真实 `account/rateLimits/read`，不缓存额度结果；完整一次读取串行化，保留 0% 窗口双读及账户核对。
- 额度专用进程临时覆盖 `features.plugins=false`、`features.remote_plugin=false`，避免启动时下载无关插件目录。普通续跑连接不使用这组覆盖参数；不修改用户持久配置。
- Keeper 创建的 app-server 保留 `CODEX_INTERNAL_APP_SERVER_REMOTE_CONTROL_DISABLED=1` 子进程环境变量；不修改桌面端的远程控制设置。该内部变量的兼容性需在 Codex CLI 更新后复核。
- 认证文件内容摘要改变时丢弃旧连接；读中改变或认证文件不可读时拒绝该次结果。读取或创建失败后关闭连接，后台按 20 秒至 5 分钟退避重建。打开菜单或点击“重新同步”可绕过后台冷却，连续失败的手动重试最短间隔 5 秒；已有查询尚未结束时合并为一次后续读取，即使旧查询成功也会执行这次明确请求。正常令牌刷新也可能触发一次保守报错和重连。
- 额度读取失败时向 `usage-transitions.jsonl` 写入 `usage_read_failed`、脱敏原因及手动/自动触发来源，原因未变的后台失败不重复记录；旧 rollout 仍只是过期的辅助信息。
- 手动刷新在 `usage-transitions.jsonl` 记录 started/queued/finished，区分 `button` 与 `menu_open` 来源，并记录请求 ID、耗时和结果；额度不变时仍能追踪刷新是否完成。
- 上游连接错误转换为跟随应用语言的提示；工作区路由发现超时单独记录为 `workspace_routing_timeout`，界面提示检查网络或代理后重新同步，不把超时直接归因于代理故障。
- 子进程管道断开返回错误，不让 SIGPIPE 终止 Keeper；应用退出只关闭自身登记的 app-server。既有执行确认、重复发送和工作区检查保留。
- 实测方法、结果与限制见 [2026-09-15 流量事故记录](流量异常修复-2026-09-15.md)。正常额度查询仍有流量，短窗口速率不能当作全天用量或代理账单。

## 执行通道与证据

- 保活：`Core/PingEngine.swift` 使用 PTY 启动交互式 Codex，隔离 home / work 位于 `~/Library/Application Support/CodexKeeper/ping/`。通过官方 `model/list` 在线确认 `gpt-5.6-luna`，支持分页，不依赖本地模型缓存。优先使用支持的 low 推理强度，否则使用模型声明的默认值；查不到时暂停保活并冷却 5 分钟，不切换到其他模型。模型查询完成后再读取额度、账户并检查计划节点。
- 保活配置生成必须使用 TOML 可接受的字符串转义，不能将路径中的 `/` 写成 `\/`。启动失败和窗口确认超时分别报告。
- 保活成功需要本次隔离任务的 OK 完成记录，以及同一账户新 5 小时窗口的真实确认；进程启动或回复 OK 本身不代表成功。
- 单次保活等待目标为 180 秒；90 秒仍未确认时显示菜单栏警示，并为本轮发送一次 macOS 通知。首次运行请求通知权限，未允许时仍保留菜单警示；前台也可展示通知。已经发出的额度查询可能使最终返回略晚于目标时间，不会另起保活请求。
- `execution-events.jsonl` 的保活 `diagnostic` 记录包含实际耗时、提醒/截止阈值、任务与轮次 ID、回复/完成/窗口状态，以及精确匹配本次任务、轮次和时间的重试证据。仅在有明确证据时区分请求超时、连接、代理和服务响应异常；无证据标未知，不记录原始终端、请求头或令牌。用户提示区分未收到回复与已收到 OK 但窗口未确认；成功或结束时清除中途警示。
- 续跑：优先通过桌面 IPC 找到原写入者并发送 `thread-follower-start-turn`；没有写入者时才使用独立 app-server。发送结果不明确时不切换通道重发。
- 按返回的 turn ID 匹配真实完成记录；带 error 的完成不能算成功。取消 Keeper 的监听不会中断桌面端原任务。
- `resume-attempts.json` 在发送前记录尝试，用于防止重复执行；不要为测试清空。

## UI 约定

- 菜单栏图标与动作一致：保活 `waveform.path.ecg`，续跑 `paperplane`，额度重置 `arrow.clockwise.circle.fill`。
- 异常 `exclamationmark.circle`，停用 `pause.circle`，同步 `arrow.triangle.2.circlepath`；悬停显示动作与时间。
- 主时间突出下一步；非今天的日期放在时间左侧，明天简写“明天”。计划外显示当前实际额度重置时间。
- 右上角仅在存在有效窗口时显示计划内 / 计划外；没有窗口时留空。
- 时间轴整体左对齐，各节点内部居中；至少两个节点才显示。完成图标只来自确认成功的执行记录。
- 额度使用两行进度条；显示值四舍五入为 0% 时单独绘制空底轨，避免原生控件的最小填充残留，非零值保留原生进度条。顶部红色条显示错误；实时读取中显示“正在同步”，读取失败且无有效额度时显示“同步失败”。刷新图标位于时间区动作文字右侧；同步中显示进度，点击立即显示正在刷新或排队提示，完成后显示更新时间或失败提示。菜单复用同一视图，在菜单跟踪期间也更新状态，避免销毁点击中的按钮。
- 续跑任务行只显示最新任务，多个任务附带总数；整行可点击，右侧有箭头，悬浮时底色、任务名和图标高亮。设置和任务窗口可调整大小，长内容可滚动。
- 设置页“保持活动”按开始时间即时显示四个“计划保活点”，跨午夜标注“次日”；说明在上、时间点在下，两者之间没有分隔线。默认发送内容为两项单选：默认文本随应用语言变化且不可编辑；自定义内容在弹窗编辑，设置页仅显示可点击的单行摘要。任务窗口编辑器仍为单层边框。
- 任务窗口标题为“自动继续任务”，发送内容选项为“使用下方内容”与“使用 Codex 输入框草稿”；前者默认取设置中的发送内容，后者只发送已保存的草稿文字，空白时发送“继续”。
- “开机自启”对应 macOS 登录项。仅系统返回需要批准时显示“请在‘系统设置 → 通用 → 登录项’中允许 Codex Keeper 登录时打开”；普通启用流程无需额外确认。
- 启用 Keeper 是总执行开关，停用显示“已停用”；旧 executionEnabled 已退役。自动续跑偏好独立保留。



## 代码地图与数据

- `App/`：生命周期、状态汇总、系统事件、菜单及窗口。
- `Core/`：日程、决策、展示模型、执行协调、尝试记录、保活与续跑。
- `Codex/`：只读额度接口、桌面 IPC、任务扫描、额度错误判定、草稿读取。
- `UI/`：菜单摘要、任务编辑、设置。
- `Tests/main.swift`：现有回归检查；`Probes/`：早期探针与原生界面示例。
- `~/Library/Application Support/CodexKeeper/`：`execution-events.jsonl`、`resume-attempts.json`、`usage-transitions.jsonl`、`pending-runtime.json`。这些运行数据独立于源码位置，搬迁不改变它们。
- 执行日志中的 started 只表示开始尝试，confirmed 才是确认成功。

## 已知边界与历史资料

- 官方额外重置的精确事件时刻没有进入当前读取的数据，检测到额度归零的时刻不能当成官方操作时刻。
- 未开启周期时，接口可能返回随查询时间滚动的重置值。5 小时窗口已通过两次读取判断；周窗口的同类显示仍需单独核实。
- 回归通过不等于完整长期稳定性验收；真实执行结果以运行日志为准。最近一次流量修复的验证结果见上述事故记录。
- `.build/` 下的旧应用、隔离副本、探针和验证记录保留用于复核，不能当作现役源码重新安装。
- 原始设计见 [V1 归档](archive/design-v1.md)，只保留设计背景，不作为当前实现规范。
